/goal 将 qiaomu-app-review-insights 收敛为一个可靠、可验证的 App 评论洞察核心产品：统一所有公开生成入口到受额度、并发去重和缓存保护的服务；禁止详情页 GET 在缓存缺失时直接触发抓取或 LLM；让首页聚焦“输入 App → 生成洞察 → 查看证据”的黄金路径并把榜单、Hacker News、机会工作台降为次级入口；为无缓存、模型不可用、生成受限和成功报告提供诚实清晰的状态；补齐关键单元/路由测试并验证本地桌面与移动端流程。
验证：运行 `npm run lint`、`npm test`、`npm run build`；增加测试证明公开 GET 无生成副作用且生成保护被集中复用；启动本地应用，使用不调用付费模型的缓存或失败状态完整检查首页与详情页，并保存桌面和移动端截图证据。
约束：保持现有缓存数据结构、公开稳定详情 URL、旧版兼容接口和用户已有未提交的 Next.js 16 升级修改；不部署生产、不写入真实凭证、不调用付费模型生成新报告，不扩大到新的研究数据源或账号系统。
边界：只修改与核心研究流程直接相关的 `src`、`tests` 和 `docs` 文件；不修改 `.env*`、生产数据、缓存数据、数据库 schema、部署配置或无关模块。
迭代策略：按“生成安全 → 状态诚实 → 首页主线 → 测试与浏览器验证”的顺序小步实施，每次有意义改动后运行最小相关检查；连续两次同类失败后必须更换证据来源、缩小复现或回退该轮方案，最多做 3 轮聚焦改进后报告剩余风险。
完成条件：公开 GET 无生成副作用有自动化测试证明，所有公开生成都经过额度/并发/缓存保护，首页和详情页能清晰表达未生成、生成中、受限、模型不可用和成功报告状态，桌面与移动端黄金路径可验证，lint、test、build 通过或只剩明确记录的非阻断警告，并提供改动文件、命令输出与截图证据。
暂停条件：必须取得生产密钥、调用付费模型、改动生产数据或部署、破坏旧缓存格式、执行破坏性操作，或需要用户决定新的目标人群和商业方向时暂停并报告。
